Mistake location punishes models that show their working before answering. claude-sonnet-5-5 scores 0.137 against claude-opus-5-5 0.819, gemini-3.1-pro-preview 0.804: the harness takes the first integer in the response as the step number, and Sonnet 5.5 works through the steps before giving its answer. Problem solving is saturated; Socratic questioning is not a ranking of tutors. The top rows solve 0.982 of the problems (claude-opus-5-5) against a leaderboard best of 0.98. On Socratic questioning GPT-4o leads the leaderboard at BLEU 0.48 and our best is gemini-3.1-pro-preview at 0.358. BLEU against a single reference question rewards phrasing that matches the reference, not whether the question teaches.

Faria, the tutor prompt over claude-haiku-4-5, sits between the leaderboard's tutoring systems and the 5.5 rows. The Faria prompt asks the model to teach rather than answer, which the harness's answer parsers score down on the solving and correction tasks.

How to read this benchmark

what one item is, what the metric means, where the published rows come from

MathTutorBench

One item is a maths problem or a tutoring dialogue: solve the problem (1,319 GSM8K items, accuracy), write the next Socratic question (BLEU against the reference question), judge whether a student solution is correct (F1), find the first wrong step (micro-F1 over the step index), correct the mistake (accuracy), or write the next teacher turn, which a pedagogical reward model compares with the ground-truth teacher turn (win rate over 1,150 dialogues; the hard sets are the 327 where the student is wrong). Published rows are the authors' leaderboard, run with thinking disabled except for the Gemini rows. Our rows use the same harness through a proxy; the Claude 5.5 family cannot disable thinking, so claude-sonnet-4-6 is the like-for-like Claude anchor. Each cell is one run with a CI95 over items; the reward model ran on Apple silicon.

TutorEval

One item is a long science passage with a student's question about it; the model answers as a tutor and a judge grades correctness and presentation on a 0–3 scale against an expert-written rubric. The metric is the mean grade as a percent of 3. Published rows used a GPT-4 judge on all 834 questions; ours use claude-sonnet-5-5 as the judge with the official template, on seeded samples of 100 and 500 and the full set for Haiku, so compare rows by judge and n. The Gemini-judge rerun of one sample measures judge disagreement, not a second contestant.

Caveats

verbatim from results.json
  1. Budget and sampling history: the first full launch on 2026-10-26 lost every unfinished task to a machine reboot ($42.16 of calls, seven task runs kept). With the $200 cap, claude-opus-5-5 and gemini-3.6-flash then ran every task on a seeded 35% subsample (run_task.py --sample 0.35 --seed 20261026, 27 Oct). On 3 Nov the cap was raised to $380 and the 65% complement of every task was run with the same seed (--complement); merge_complement.py recomputes each metric on the union exactly as the harness does (item-weighted accuracy and micro-F1; sacrebleu, sklearn F1 and reward-model wins recomputed on the concatenated per-item lists; each part re-scored equals its own yaml), so those rows are now full-set, with both parts kept under results -> parts. TutorEval: claude-haiku-5-5 on all 834 (the 100 seeded-sample items reused their 27 Oct generations and grades); claude-sonnet-5-5 on a seed-0 sample of 500 (superset of the sample-100, 4 Nov) and faria-v5-haiku-4-5 on the seeded sample of 100 (seed 0).
  2. Thinking: the leaderboard note says all rows except the Gemini ones ran with thinking disabled. Claude Sonnet 5.5 / Haiku 5.5 / Opus 5.5 have adaptive thinking that cannot be disabled, so those rows are not like-for-like with the leaderboard's Claude Sonnet 4.6 row; Sonnet 4.6 (no thinking) is the clean comparison.
  3. Temperature: the harness sends temperature=0; the Claude 5.5 family returns HTTP 400 for any explicit temperature, so the proxy hook drops it (default sampling). Gemini and Sonnet 4.6 / Haiku 4.5 ran at 0.
  4. Stop sequences: the Anthropic API rejects whitespace-only stop strings ('\n\n' in the four pedagogy tasks, '\n' in socratic questioning). The proxy removes them from the request and truncates the returned text at the earliest occurrence, which is what a server-side stop produces. How the authors' OpenRouter run handled this is not documented.
  5. System-only prompts: the harness sends the dialog-task prompt as a system message with no user turn (is_chat=True). The Anthropic API requires a user message, so LiteLLM's modify_params inserts a placeholder user turn ('.'). The Faria contestant instead uses the harness's prompt_as_user=True so the Faria prompt can occupy the system slot.
  6. Parsing is part of the benchmark: mistake_location takes the FIRST integer in the response, problem_solving the LAST number, solution_correctness the first 'yes'/'no' substring. Models that explain before answering (the thinking models in particular) lose points to the parser; we did not alter it.
  7. The repo's --debug flag is parsed but unused in main.py at commit 6faed17; pilots used our run_task.py --limit wrapper (first N test items). visualize.py referenced in the README does not exist at this commit.
  8. Cost attribution per task uses one LiteLLM alias per (contestant, task); Gemini usage is read from the legacy SDK's usage_metadata (thoughts billed as output = total - prompt tokens). Prices from the conductor brief (Anthropic) and ai.google.dev pricing (Gemini) as of 2026-10-26.
  9. Reward-model win rates were computed on Apple M4 (torch 2.3.1, bf16) with the official scorer script; the authors used a GPU. Small numeric differences in logits are possible; the comparison chosen > rejected is a strict inequality.
  10. TutorEval (if run): judge is claude-sonnet-5-5 with the official grading template verbatim instead of gpt-4-1106-preview; the repo's OpenAI path used temperature 0.7, which the 5.5 judge cannot take. Published rows used the GPT-4 judge, so absolute numbers are a band, not a rank.
  11. Gemini usage logging: until 2026-10-27 run_task.py logged chat-path calls twice (send_message calls generate_content, both were patched), so the gemini-3.6-flash pilot and aborted-attempt ledger rows were overstated by $1.58; correction rows are in the ledger and reconcile_reboot.py deduplicates those historical logs. Per-call cost projections were unaffected (rows and tokens doubled together).
  12. Prompt placement sensitivity: the harness sends dialog-task prompts as a system message with no user turn, so the Anthropic API sees the proxy's placeholder user turn ('.'). Re-running claude-sonnet-4-6 on the two scaffolding tasks with prompt_as_user=True raises its win rate by 0.062 (scaffolding) and 0.070 (scaffolding hard); the Results table keeps the harness-default rows, which is also how the leaderboard's Sonnet 4.6 row was produced. The prompt-as-user rows are in results with sensitivity_of set.
  13. TutorEval judge check: the claude-sonnet-5-5 sample-100 answers re-graded by gemini-3.1-pro-preview (through the proxy, default thinking, max_tokens 4096) score 96.17 / 99.0 against 91.67 / 95.50 under the Sonnet 5.5 judge, and the Gemini judge is >= the Sonnet judge on 95 of 99 items, so the same-family concern runs the other way (the Sonnet judge is the stricter one). One of the 100 Gemini gradings had no GRADE line and is scored 0/0 by the official parser (97.14 / 100.0 excluding it).
  14. One run per cell, no repeats; CI95 covers item sampling only. The merged opus / gemini-3.6 rows are one run per item like the others (each item was generated exactly once, in one of the two launches).
  15. Reward-model cells against the leaderboard: for the three anchors run on both sides, the harness-scored cells agree within 0.04, but our win rates are below the leaderboard's on scaffolding hard for all three (claude-sonnet-4.6 -0.08, gemini-3.6-flash -0.04, gemini-3.1-pro -0.07) and on scaffolding for Sonnet 4.6 (-0.09); the pedagogy-following cells are within 0.03. Candidate causes: the scorer setup (official script on Apple M4, bf16, batched forward passes; 64-pair batched-vs-unbatched check only) and, for the Claude anchor, the system-only prompt placement (+0.06/+0.07 when the prompt is the user turn). Our contestants are all scored the same way, so within-table comparisons hold; cross-table comparisons on the scaffolding cells carry this offset.
  16. Spend: the ledger closes at $381.78, $1.78 over the $380 cap (the claude-sonnet-5-5 TutorEval sample-500 run came in $1.29 over its $17 plan and gemini-3.1-pro-preview $0.38 over the $108 projection it was sized against); no run was started after the overrun was known. The gemini-3.1-pro-preview total includes a $4.89 mistake_correction attempt that died on a 504 DeadlineExceeded at item 353 and was rerun.

Faria hill-climb (4 Nov, lane HF, hillclimb/README.md): nine prompt variants were screened on the seeded 35% subsample over claude-haiku-5-5 and three promoted to claude-sonnet-5-5, with the two 402-item pedagogy cells scored on their first 200 pairs only for the screen (hard cells and all guardrails in full; every baseline compared on the same slice); the two winners were then scored in full and run on the 65% complement, so their rows are full-set like the others.
